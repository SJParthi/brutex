### `lattice.rs` — the BUC iceberg cube (D-6400, D-6401, D-6404..D-6408, D-6410)

- **`RowTable`**: ONE partition — one (direction, entry style, timeframe),
  long and short never pooled — of decisions in canonical order (day, decision
  second, stock slot, decision id). Each row carries one outcome index per exit
  variant of the run's generated exit set (FM-F054; the exit row is never
  OPEN, and the lattice assumes no exit count). `push_month` appends one month
  as a block put in order by two stable counting sorts over the month's own
  second and day domains (FM-F051); no earlier month is re-sorted. Every
  refusal is a named `LatticeRefusal` (22 of them, each named once) and leaves
  the table unchanged.
- **`walk(table, min_support, schedule, visitor)`**: grows one-direction mixes
  from the partition's root by fixing one free row at a time, in row order. A
  categorical row's children come from one stable counting sort of the node's
  rows; the cumulative `mover_rank` row's children are nested prefixes, each
  built by one stable linear scan of the parent's canonical range (FM-F055), so
  every node's rows stay in canonical time order. A child is visited iff its
  RAW trade count reaches `min_support`: growth is by trade count only, the
  lattice reads no gate verdict, and there is no depth, `k` or `max_level`
  anywhere (a source test refuses the words). The 21 free rows of schema v1
  (`FREE_ROWS`) are a structural bound of the schema, not a parameter. A child
  equal to its parent is skipped as `equivalent_to_parent` (D-6401); a prefix
  equal to the one before it is skipped as `equivalent_to_sibling` (FM-F103);
  both are counted and never scored.
- **`Tally`**: frequent, equivalent-to-parent, equivalent-to-sibling and
  infrequent nodes by the number of FIXED ROWS in the mix, and row-touches.
  `Tally::mixes(variants)` is the trial count (every visited node scores every
  exit variant as its own mix, D-6405).
- **Locality (D-6406)**: every node region carries its rows' cells beside their
  indices (an SoA arena), so the per-touch work never gathers from the table.
  Scratch per worker is at most 21 x rows x 28 bytes, reserved once, committed
  by the allocator only as the walk writes (L-FIB6-02).
- **Work stealing (FM-F053, D-6410)**: `Schedule::Parallel { split_support,
  batch_budget_bytes }` splits a node of at least `split_support` rows into
  rayon tasks with forked visitors absorbed in preorder, so outputs are
  byte-identical to the sequential walk with no sort; a batch whose task
  scratch would pass the budget runs inline and is counted (`Spread`).
- **Guided mode (FM-F052, D-6408)**: `Survivors` (a trie of survivor keys in
  binding order), `walk_guided` (only trie paths, the equivalence skip and the
  floor disabled on them, so a lone survivor equal to its parent IS scored),
  and `reconcile` (a survivor with no verdict, a verdict with no survivor or a
  repeated one FAILS by name).
- **`expand_range`**: one node's expansion over a contiguous range — the
  walk's unit of work and the bench's `C-F6-01`.

### `score.rs` — the ordered scoring pass (D-6402, D-6403, D-6409, D-6410)

- **`OrderedPass`**: one canonical-order pass over a visited mix's rows for
  every profile (the run's own exits x the two report sizes, FM-F117) with ONE
  POSITION PER (profile, stock). A candidate whose decision second is at or
  before the open position's block-until second is skipped and counted.
  Blocking follows the outcome (FM-F056): a priced slot blocks to its exit
  second, a pending order to its window end, an unpriced slot (no execution
  seconds, factor refused, forced exit unpriceable, feed hole, corrupt bar) to
  the end of the stock-day, a zero-quantity or inapplicable slot blocks
  nothing; ties go by decision-id order and are counted. The raw count still
  bounds the effective count, so the lattice's raw-count prune loses no mix.
- **Epoch-stamped scratch (FM-F050, D-6409)**: block slots stamped with their
  day, touched-month lists, and period state updated only on days with trades,
  so a mix costs O(support x profiles + touched months), never
  O(days x pool). One pass reused across mixes equals a fresh pass per mix,
  bit for bit.
- **Net, never gross**: `ChargeModel` is a per (stock, day) accumulator
  (`add(order)` O(1), `close_day` the rounding adjustment); `Gross` is the
  zero model, a labelled plumbing run only (D-6410; FIB-11 supplies CHG-1's).
  A trade WINS only if its net money is above zero; zero is a loss. Net R is
  net money over (quantity x risk per share).
- **`MonthStats`** per month and profile (counts, wins, losses, sums of R,
  win R, loss R, R squared, max and min R, money, per side value, stops in bp,
  MAE and MFE in R, unpriced count; the 5R/10R/20R giant-winner columns are
  replaced by FIB-1 R4's report ladders, as `FIB-01.md` says), and a **`Card`**
  per mix and profile: streaks in entry order, drawdown at each day close in R
  (peak, depth, longest length and recovery in tradable days; the first lowest
  close is the trough and the first of equally deep episodes the deepest),
  period tables for seven kinds (day, week, fortnight, month, quarter,
  half-year, year: worst, best, second best, winning share), MAE and MFE sums,
  and FIB-1 R4's report ladders (one counter per rung per month, exact
  rational comparisons). Every figure carries `SCORECARD_LABEL` —
  "information", never a decision: the gate's downside checks are FIB-7's.
  Statistics are `f64` at full precision summed in canonical order; money is
  `i128`.
- **`CardSink`**: a visitor that scores every visited mix and serialises its
  cards (`Card::push_bytes`), the byte stream the parallel-equals-sequential
  test compares.

Equities stay research: nothing here charges a trade (the `Gross` model is
plumbing), and no result of this package enters Selection V6 or execution
authority.
