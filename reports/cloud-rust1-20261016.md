## p50 / p99 / max, before and after

**Method.** The base commit `4756cce0` was built in a separate worktree, and this change in the main tree, each with the same ignored timing harness added to `disk_route`'s tests. The two test binaries ran in three interleaved rounds (before, after, before, …), each time with `--ignored rust1_ --test-threads=1`. Each figure: 50 warm-up calls, then n = 1,000 timed calls with `Instant`, sorted, nearest rank (p50 = 500th, p99 = 990th, max = 1,000th). Root: an empty store in a fresh temporary directory under `/tmp` (ext4/overlay, 4096-byte fragments). The handler rows call `disk_json` on a 4-worker tokio runtime through `run_ops_read`'s admission and blocking pool, as a request does; HTTP framing is not timed. "Miss" clears the 30 s cache before every call. The harness was removed before the final commit. Ranges are across the three rounds.

## Gate proof

| Proof | Result |
|---|---|
| Real tree before the change (`4756cce0` plus the new test file) | `no_shipped_code_starts_a_program_outside_the_allowlist` **FAILED** with exactly one line: `crates/api/src/disk_route.rs:127 in fn measure names the process-spawning type: a process spawn outside test code is not allowed` |
| Real tree after the change | **passes**. `server.rs`'s `open_unless_suppressed` matches its one allowlist entry, and the test-code namings (`mkfifo`, `git`, the test binary re-running itself) are seen and exempted (asserted ≥ 20). |
| Planted spawn, synthetic sources | Refused, by file, line and function, in 14 spellings: the full path; spaced `std :: process :: Command`; `tokio::process`; raw `r#Command`; a `use` of the type; an import group; a glob import; a renamed module (`process as p`); under `cfg(any(test, ..))`; under `cfg(not(test))`; after a `'"'` char literal; after a lifetime; in the field after a gated field; in a `macro_rules!` body. The first case's whole failure text is pinned. |
| Exempt cases, synthetic | Not refused: `#[cfg(test)] mod` (with or without more attributes), `#[test]`, `cfg(all(test, unix))`, `cfg(any(test, all(test, ..)))`, a generic test fn, `#![cfg(test)]`, a gated statement, a line comment, a nested block comment, a string, a raw string, `process::Stdio`, `process::exit`, `CommandExt`, another crate's `Command` type. The exempt spawn is still counted (seen = 1). |
| Unreadable file | An unclosed block comment, string or raw string fails as "cannot be read by this scan". |
| Test-code rule, synthetic trees | A `#[cfg(test)] mod` exempts its file and that file's own modules; without the attribute both ship. `#[path]` works, as do non-`mod.rs` stems, inline modules, modules inside a test-only inline module, and `include!` (exempt in test code, shipped in shipped code). A `#![cfg(test)]` file exempts its modules, and a crate root's modules sit beside it. An undeclared `x_tests.rs` is refused by name. A missing test-only `mod` or `include!` target is refused by name. `tests/` is exempt; `benches/`, `examples/`, `src/bin/` and `src/tests/` are not. |
| Allowlist exactness | Two namings in the allowed fn fail ("is allowed 1 and holds 2"). Another fn fails. A nested fn is its own scope. The same fn name in another file fails. A stale entry fails. |
| How test code is decided | Written in the module doc of `no_runtime_spawn.rs`, "How it decides what is test code", and in D-5240 item 3. |

Two defects in the first draft of the gate were found by running it on the real tree, and both were fixed before it was trusted:
- An `include!` inside a test module was not followed. `crates/cli/src/step3_orchestrator.rs` pastes `strict_v6_tests.rs` that way.
- A file that was test code by its own `#![cfg(test)]` was not expanded. `gdfl_import_tests.rs` declares three more `*_tests.rs` files.

I checked every `process::Command` mention in the 17 shipped-module files that hold one by hand. Each is in a test module, in a test-only file (`api/src/isolated.rs` is `#[cfg(test)] mod isolated`), or in a doc comment (`store/src/flock.rs:12`).
