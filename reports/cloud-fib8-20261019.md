## The stock-day reader: FIB-5's and FIB-9's entry points (D-6453)

`runner` (FIB-5's walker) cannot name `cli` — the arrow runs `cli → runner`
(`CLAUDE.md` §5) — so the walker's caller is FIB-9's `cli` run (or a FIB-5
real-data command in `cli`), and FIB-8 hands it every ingredient by type. All
in `crates/cli/src/fib/day.rs`, all public:

```rust
use cli::fib::authorities::Authorities;
use cli::fib::day::{
    read_stock_month, DaySeconds, PreviousReference, StockDay, StockMonth, StockMonthSpec,
    StockState,
};

let authorities = Authorities::interim(&present)?;          // or FIB-10's set, each by name
let mut state = StockState::first_day();                    // FIB-9 checkpoints it per stock
let month: StockMonth = read_stock_month(
    root,                                                   // the store root (BRUTEX_STORE)
    &StockMonthSpec {
        symbol: "RELIANCE",                                 // masters and the 1day variant
        series,                                             // the pool's SeriesId
        when: (2025, 3),
        widths: &[1, 5, 15],                                // the Generation's widths (R7)
        reference: PreviousReference::TradableDay,          // recorded, never defaulted
        seconds: true,                                      // the deep stage's GDFL 1s
    },
    &authorities,
    &mut state,
)?;                                                         // Err(Halt { word, detail }) by name
for day in month.days() {                                   // or month.day(ist_day): O(1)
    let StockDay { input, seconds, halt } = day;
    // input: &DayInput — calendar verdict (input.tradable), refusal, admitted(),
    //        the previous closes, candidate_refusal(), the closes table, sides, stamps.
}
```

| FIB-5's `runner::fib::walk::DayInput` field | Where FIB-8 has it |
|---|---|
| `bars`, stage A | `day.input.minutes` — the day's REAL Zerodha minutes inside the continuous window, in order; a padded no-trade minute (FM-F095) is a hole and is not there |
| `bars`, deep | `DaySeconds::Held(seconds)` → `seconds.bars()` — the GDFL seconds kept, ascending, unique, continuous phase, inside the day's window; `Refused(word)` and `NoExecutionSeconds` name a day with none; `NotRead` when stage A asked for none |
| `halts` | `day.halt: Option<pull::calendar::HaltSeconds>` — `HaltRange { start_second: halt.from, end_second: halt.resume }` |
| `zerodha_minutes` (deep) | `day.input.minutes` |
| `trail` | `day.input.candles: Vec<WidthCandles>` — `TrailCandles { tf_minutes: w.width, candles: &w.candles }`; a withheld bucket is `complete = false` and named in `w.withheld` |
| `max_second_gap` | `seconds.longest_gap()` is the day's own reading (the most consecutive missing seconds between two kept seconds); FIB-2's `MaxSecondGap` folds it over the committed past days — that fold is FIB-2's/FIB-9's, not built here |
| `book` | not FIB-8's: OF-1 is absent in the interim (`BookEvidence::NotObserved`) |
| `clock_lag` | not FIB-8's: DATA-1/PREC-13; under the interim `--seconds unchecked` authority it is `ClockLag::TrustUnchecked` |
| `raw_tick`, `decision_tick` | not FIB-8's: no observed-tick reader is in FIB-8's specification |

A width added to a Generation later is folded for the stock-days already held
with `DayInput::fold_width(width, &cash)` (D-6454), byte-equal to building
with it from the start.

The same reader is `cli fib day-check SYM YYYY-MM --previous tradable-day
--authorities interim [--deep] [--json] [--reference]`: `--deep` adds each
day's seconds verdict, its longest gap and its halt (`--seconds WORD` already
names the seconds-trust authority, so the flag is `--deep`).
