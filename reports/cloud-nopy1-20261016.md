## 2. The gate test

`no_float.rs`'s closed list of vocab test files, which fails on an unlisted one.

**The gate:** `no_tracked_file_is_runs_or_names_the_py_language`. It reads every
file `git ls-files` lists, every byte, and fails on any of:

| Refused | How |
|---|---|
| The name in a file's bytes | any case, mid-word, beside a NUL, in non-UTF-8 bytes; reported by line, masked as `[THE NAME]` |
| The name in a file's path | any case |
| A file of the language | extension `py`, `pyi`, `pyc`, `pyo`, `pyw`, `pyd`, `pyz`, `ipynb`, any case; `web/` included |
| A shebang running the interpreter | any line starting `#!` (not `#![`, a Rust inner attribute); the program directly or through `env` (flags and `NAME=value` skipped); refused when it holds the name or is `py`, `pypy`, `jython` or `graalpy` after `.exe` and a trailing version are taken off |
| A walk of nothing | fewer than 1,001 files read |
| The exception drifting | D-0207's exact line must be excused exactly once: a copy fails, its removal fails |

The needle is `concat!("py", "thon")`-style halves with a six-letter tripwire,
so the gate's own file never holds the word (proved by the file scanning itself
clean). With no `.git` (a `cargo-mutants` copy) or no runnable `git`, it walks
the directory instead, skipping `.git`, the root `target` and every
`node_modules`, and prints `WALKED AS A DIRECTORY`; a `.git` that `git` cannot
list is a failure, not a walk.
