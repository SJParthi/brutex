```text
R4-09b: the store's backup verb and its restore drill (AUT-06), split out of R4-09 (operator, 23 Oct 2026 ~08:50 IST: "move R4-09's backup and restore drill up, right behind the critical path"). Decision D-7137 (block D-7135..D-7144). SOURCE ITEM AUT-06 (state/data-census-20261013/ingest-db-checklist.json): "There is an independent second copy of the store and the source archives, with a restore drill, and the app says when it was last checked." Proposal: a Rust verb that copies new and changed immutable files (bar months, generations, journals, census epochs, source archives by name and size) to a second drive with checksums, records a manifest, and a restore drill on a sample; /disk.json then says recorded: true with the date. Acceptance: after a run, a sample restore of 3 months compares byte-equal; /disk.json shows the manifest date; with the second drive missing, the page says the backup is stale.

BUILD
1. `cli backup --to <dir> [--plan] [--mib-per-s N]`:
   - Walks what the store already lists (served and older generations, journals, census epochs, ledgers, ops/ files) and the GDFL source archives by name and size. It never globs the whole drive.
   - Copies each new or changed file to <dir> as tmp + fsync + rename + folder fsync, with a blake3 digest. It never deletes or overwrites a file on the target: a changed source is a new name there, the old one kept.
   - Appends one manifest record per file (path, length, digest, source mtime, run id) to an append-only manifest on the target. Its lookup is O(1) per file (a fixed-stride index or a map built once), never a rescan of the manifest per file.
   - Holds the month reader lock while it copies a month. A writer-held month is a named 'busy' line and is retried later, never copied half-written.
   - Refuses by name: a target on the same device as the store (st_dev), a target inside the store, a target with less free space than the plan needs, and a target that is not a directory.
   - --plan prints file counts and bytes, and copies nothing.
   - On success, appends the receipt line that docs/36 §4 and api's disk_route.rs already read from <store>/ops/backups.log (reuse that exact format; no second parser).
   - Idempotent: a second run copies nothing and appends a receipt that says so. Resumable: a kill mid-copy leaves no file the manifest calls done, and the next run finishes it.
2. `cli backup-drill --from <dir> [--months N]` (N defaults to 3): restores N months (chosen from the manifest, across kinds) into a private scratch root (role=scratch), compares them byte for byte with the store and with the manifest digests, and appends one drill line (date, months, result). It never writes into the store.
3. /disk.json and the /db band show the last backup date, the manifest's file count and bytes, the last drill date and its result. Staleness is computed when the page is read, from the age of the last backup and the target's presence, and shown by name ("backup stale: last copy <date>; target missing"). No alert kind is added (R4-05 adds no kind without a producer; D-6900 is attended only).
4. LOCAL-ONLY ITEMS (FM-277): docs/36 §4 lists each item that lives only on this Mac, with its second copy or "none": the untracked local configuration (copied to the target as a file only, never into git, never printed; CLAUDE.md §8), unpushed commits, the work folder's state/. The operator decides what is covered. The verb copies only what --to and the list name, never a credential value.
5. O(1) and limits: the per-file step (manifest lookup, digest record) is O(1); measure p50/p99/max (n >= 200). A full copy is O(bytes) by nature: docs/06 records it as a one-time pass with a measured sample rate and a projection labelled as an extrapolation.

FILES: crates/cli/src/backup.rs (new); cli's verb table (a one-line registration; sequenced with any part editing it); crates/api/src/disk_route.rs (read side only; if SC-8 has merged its /disk.json edit, rebase onto it, never revert it); docs/36 §4; docs/04 rows; docs/05 entry D-7137; docs/06 one-time pass row. It does not touch pull/src/scrub.rs (SC-9), store/src/file.rs, or R4-09's scrub schedule or /verify work.

TESTS, each failing first: a_second_backup_copies_nothing; a_changed_file_gets_a_new_copy_and_the_old_copy_stays; a_target_on_the_store_device_is_refused; a_target_inside_the_store_is_refused; a_kill_mid_copy_resumes_without_a_torn_file; a_writer_held_month_is_busy_and_retried; the_drill_restores_three_months_byte_equal; disk_json_shows_the_manifest_and_drill_dates; a_missing_target_reads_as_backup_stale; the_receipt_line_is_read_by_the_existing_backups_log_parser. Private roots only; at least 8 extreme cases, 2 of them combinations and 1 out-of-the-box (for example a target that fills up mid-copy while a month is writer-held).

STORE WRITES NEEDED (operator's yes): the operator names the second drive's path. A --plan first, then a measured sample, then the first full copy. Its size is the store (about 913 GiB on 7 Oct) plus the source archives (about 0.6 TB), so the second drive needs about 1.6 TB or more (an extrapolation, measured by --plan first). Then one drill on 3 months.
```
