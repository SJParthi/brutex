| h-pull-1 | medium | lake | crates/lake/src/schema.rs:164-178 (`detect`) and :218-238 (`misread_timestamp`) | The timestamp unit guard (hunt-store-5, D-1528) only reads the Parquet **logical** type. A file that marks `timestamp` with the legacy **ConvertedType** `TIMESTAMP_MILLIS` (or `TIMESTAMP_MICROS`) and no LogicalType reaches `misread_timestamp(None)`. That returns "accepted", so milliseconds are decoded as microseconds: each stamp is 1000x too small and lands in January 1970. Nothing refuses it. parquet-59.2 `schema/types.rs:1346-1349` keeps `converted_type` separate and never turns it into a `logical_type` on read. The code says the real lake's declaration is UNVERIFIED, and older writers (parquet-mr, older pyarrow) emit converted-only types. This is the §4 silent-wrong-value class. | Probe `crates/lake/tests/zz_hunt_1.rs`: a 7-column cash file whose `timestamp` has `.with_converted_type(ConvertedType::TIMESTAMP_MILLIS)` and value 1_704_080_700_000 (2024-01-01 09:15 IST, in ms). Output: `open: Ok(())` and `PROBE timestamp_micros read = 1704080700000 (file holds MILLIS 1704080700000); as micros that is 1704080 s after epoch`. So it opened, decoded, and was not refused. | In `detect`, also read `col.converted_type()`. Refuse `TIMESTAMP_MILLIS` with `UnsupportedTimestamp`, and refuse any converted type other than `NONE`/`TIMESTAMP_MICROS` on `timestamp` (and any other than `NONE` on the INT64 count columns). Add a refusal test beside `lake::reader` that uses a converted-only file. |
| h-pull-2 | low | pull | crates/pull/src/totp.rs:222-275 (`decode_alphabet`) | The base32 secret decoder ignores leftover bits. It accepts lengths that RFC 4648 says are impossible (1, 3 or 6 characters past a whole 8-char group), and it accepts non-zero pad bits. So a mis-keyed or extra trailing character is silently dropped and two different secret strings decode to the same key. D-1373 closed this exact class for `=` ("a mis-transcribed secret ... produced a valid-looking code") and left the trailing-bits door open. | Probe `crates/pull/tests/zz_hunt_1.rs`: `PROBE base32 GEZDGNBV=[49, 50, 51, 52, 53] GEZDGNBVA=[49, 50, 51, 52, 53] GEZDGNBV7=[49, 50, 51, 52, 53]` and `PROBE codes 662488 662488`. A 9-character secret (an invalid base32 length) gives the same key and the same TOTP code as the 8-character one. | After the loop, refuse when `bits >= 5` (a whole spare character, which means an invalid length) or when `acc & ((1 << bits) - 1) != 0` (non-zero pad bits). Return `TotpError::NotBase32` naming the last byte, and add a test beside `padding_inside_the_secret_is_refused_and_only_a_tail_is_skipped`. |
