# hunt-store: format semantics of crates/store, crates/lake and crates/core at 1087e54

## Verdict

At 1087e54 the bar format's bytes match `docs/02-store-format.md`. Header slot offsets 0..64, the little-endian encoding, the CRC-32C domain (0..56 plus 60..64, header.rs `covered`), stride 56, the 73-record / 4,088-byte blocks, the sidecar at `block*4`, and the slot position `g % 2` at a 16,384-byte stride all agree. The append order is records, fsync, sidecar, fsync, slot, fsync (file.rs `append`). No crate maps a file (§4 holds). The read path decodes the slot from a single 64-byte copy and checks magic, then version, then CRC, and only after that reads the stride, reserved bytes, flags or length (header.rs `decode_parts`). Every block is CRC-verified before a record is served, and the record is served from the verified buffer (D-1433). Every prior store, lake and core finding from the 2026-10-02 pass that I re-checked is FIXED: probestore-3/4/5/6/7a and o1store-1/2.

The new defects are at the edges:
- **hunt-store-1 (medium):** the ordinary bar door accepts an overlay or greeks file at a `.bin` name and serves fabricated bars.
- **hunt-store-2 (low):** an empty month whose genesis slot write tore can never be opened again.
- **hunt-store-3 (low):** the writer silently recreates a missing store root.
- **hunt-store-4 (low):** the writer fsyncs only the leaf directory, not the parent directories it created.
- **hunt-store-5 (low):** lake never checks the timestamp column's unit or UTC flag.
- **hunt-store-7 (low, tests):** four catalog tests fail as root because D-0995's migration missed them.
- **hunt-store-6, 8, 9, 10:** documentation drift.

Core universe lists are correct: FNO_UNDERLYINGS has 213 entries, which is 208 shares plus 5 indices. There are no duplicates and the list is byte-sorted. The ISIN array is aligned and has exactly 5 `ISIN_ABSENT` entries, at the 5 index rows. The NIFTY 50 ⊂ 100 ⊂ 200 ⊂ 500 ⊂ Total Market chain holds, and the 208 F&O shares are all in Total Market.

The task mentions "lake parquet export", but there is none. `crates/lake` is a reader only, and nothing in the workspace depends on it (lib.rs:67-68).

## Checks that held

- Slot layout, slot CRC domain and check order: header.rs:112-140 offsets, `decode_parts` (magic → version → magic/version match → CRC → stride → reserved → flags), `covered()`.
- Generation and counter wrap are refused (`advance`). A misplaced slot refuses the whole read (`best_candidate`). A truncation to an older commit is refused through `highest_claim` (file.rs `validated`).
- Commit order matches §5. Records are made durable before the slot. The sidecar entry is written before the slot. A tail sealed past the commit is admitted only on the CRC-extension proof, bounded to the nominal block (block.rs `sealed_past_the_commit`).
- Append-only: the only offset `append` writes records at is `offset_of(n_valid)`, which is past the committed extent. Overlapping batches are byte-compared and never rewritten (`already_stored`, `suffix_that_follows`). A sealed month that has lost its `.crc` cannot get a new sidecar (`create(fresh)` with `fresh = n_valid == 0`). Repair writes to `bar-revisions-v1/<ordinal>/` and never touches the original.
- Locking: the writer takes `flock` `try_lock` on `.lock` before it opens or measures `.bin`. Readers take `try_lock_shared`. The lock is released by explicit `unlock`, not on drop of a duplicated descriptor (flock.rs, D-0693). Stale locks cannot occur because the kernel frees a flock when the process dies. The documented limits are NFS, symlinks and non-cooperating writers (file.rs:60-76).
- No writable mmap: `#![forbid(unsafe_code)]`, there is no `memmap2`, and positional I/O is used throughout.
- Universe counts and sort order, verified by extracting the arrays with awk/sort/comm (commands in the session).
