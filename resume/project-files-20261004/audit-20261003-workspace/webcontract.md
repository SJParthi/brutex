# webcontract — the web/ ↔ crates/api boundary at 1087e54

## Verdict

The route-level contract holds. Every one of the 51 distinct API paths in the tracked bundle `web/build` is registered in `route_table` (server.rs:16068-16382) or in `audited_router_serving` (`/inspection.json`, server.rs:15815). Every POST call site uses POST.

The headline precision risk is handled. `mask_words` travels as six decimal **strings** on every producer: backtest.rs:699-706, frontierjson.rs:399, livejson.rs:208, sweepevidence.rs:231, candidatejson.rs:349, expressionsearchjson.rs:169. The browser decodes them with `BigInt` and refuses anything non-canonical (web/src/lib/mask.js:33-48), so values above 2^53 do not lose precision.

`web/build` matches `web/src`. I recomputed the source digest from svelte.config.js with sha256sum and got `d788a1f0988de90c`, the same as `web/build/_app/version.json`. No `web/` source file changed after the rebuild commit ad2c057 except tests and CI.

The static file server held against every traversal spelling I sent it, verified by a Rust probe.

I found **three NEW real defects** and **two NEW info-level items**:
- A field the page needs is never sent: `/vocab.json` has no `commit_digest`. As a result the research tester can never name a condition.
- `web/masters.js` puts strings from the API and from vendors into `innerHTML` without escaping them.
- `/masters` hides a failed re-parse, and its footer contradicts the server's reload.
- Info: the version digest leaves out three imported helpers.
- Info: static assets are served with no caching headers at all.
