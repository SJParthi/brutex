# hunt-cli-a — crates/cli selection/population/execution/ledger/results/trades @ 1087e54

**Verdict.** The CLAUDE.md §1 law holds structurally at HEAD. No equity result can reach Selection V1–V6 or Execution V3/V4. Every family type on those paths is a closed two-variant enum, NIFTY or BANKNIFTY, and nothing accepts a symbol. VIX appears nowhere in ranking or identity code in the scoped files. Every version reader I checked compares its version for exact equality (`!=`). The one deliberate exception is `results.rs`, which reads v2 and v3 but appends only v3, and that is documented. Codecs I checked (results Record, trades Row, result_set Receipt) are symmetric. Provenance banners are present on ledger-v6, ledger-v6-replay, ledger-all and pool, and pool states GROSS OF EVERY CHARGE without condition.

The new defects are in duplicate-run detection. D-0936 (W2-cli14-5) fixed "rewrite an indexed record and also grow the file" for Selection V1–V3 only. The same gap is still live in `results/runs.bin` and `results/detail-sets.bin`, and a Rust probe proved both. The probe also showed that `runs.bin`'s cold open silently accepts a duplicate identity that `detail-sets.bin` refuses. Pool's refusal ordering is still present (KNOWN).

Probe: `crates/cli/tests/zz_audit_hunt-cli-a_1.rs`, run with `cargo test -p cli --test zz_audit_hunt-cli-a_1 -- --nocapture --test-threads=1`. All 3 passed (they print, not assert). The file was deleted afterwards and `git status --porcelain` shows nothing of mine.
