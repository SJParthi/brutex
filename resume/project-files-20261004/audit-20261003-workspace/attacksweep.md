# attacksweep: adversarial attack on the sweep and surface path (vocab, engine, runner, cli, api, telemetry) at 1087e54

**Verdict.** I found no silent wrong answer in the sweep itself. A brute-force subset oracle agreed with `engine::Ladder::walk` on 12 random columns, which together held 97,000 frequent itemsets: 0 missing, 0 extra. Sweeps were byte-equal at 1, 2, 3, 4, 7 and 64 support lanes, including sweeps that halted on the candidate ceiling or the pair budget. Every truncation of an engine checkpoint was refused. Resuming from every boundary reproduced the full sweep exactly. The Newey-West t matched an exactly-centred recomputation for means up to 1.5e7 paisa. The cli rejected every extreme argument with exit code 2 and never panicked, and reruns were byte-identical. Three new defects are on the surface side:

1. **The probeapi-1 slowloris fix can be bypassed with two bytes (medium).** A connection that sends `\n\n` or `\r\n\r\n` and then goes silent is never cut. A few such connections fill the connection cap, and real requests then get no answer.
2. **A telemetry event can be reported `Written` and still be lost (low).** When the disk is still full, the newline that should close a partial line also fails. The next successful event is then glued onto the partial line and cannot be read back.
3. **Repeated keys in a POST form body are still answered from the first value (low).** The probeapi-5 fix covered the query string only.

The known cli test `generated_search_recovers_same_ordinal_and_refuses_missing_ancestry` **passes** at HEAD when run alone (116 s).

All probes were Rust files at `crates/<crate>/tests/zz_audit_attacksweep_<n>.rs`, run after BUILD_DONE and then deleted. At the end, `git status --porcelain` shows only `crates/pull/tests/zz_audit_attackdata_2.rs`, which belongs to another worker.
