# testgaps — invariant/test/ledger hygiene audit at 1087e54

**Verdict.** The test surface is mostly sound. Of 6,535 `#[test]` functions found by a scan, none is a true empty test. The 42 bodies with no inline assertion either hand off to helpers that do assert, or are two compile-time type-pin tests. The ledger has no conflict markers. Every duplicate or unissued D-number is already documented (D-0684, D-0104). There are four real gaps, all NEW:

1. Gate 10 checks only `a::b::c` tokens (three or more segments) and bare names written as "name in `crates/...`". About 1,160 proof tokens are outside that: 303 two-segment tokens and 857 bare names. I found **four `✓` invariant rows that cite a test that does not exist** (ER-01, MR-23, AD-02, ED-01). Three were renamed and one was never written.
2. Eleven invariant rows (04-invariants.md:4386-4932) are proven only by native Rust tests under `web/`. Neither `cargo test` nor any CI step compiles or runs them.
3. Twelve `#[ignore]`d tests never run in CI. Nothing in `.github/workflows` passes `--ignored`. One of them is cited as proof with no label.
4. `docs/06-limits.md` §93 and §82 name things that no longer exist: `cli::derived_ceiling` and `.github/workflows/web.yml`. `crates/cli/src/lib.rs` still has rustdoc links to the removed function.

The root-only test failures are KNOWN and were re-confirmed by a run.

## Method (commands actually run)
- Test inventory: scanned all tracked `crates/**/*.rs` and `.github/*.rs` for `#[test]`/`#[tokio::test]` followed by `fn`. Result: 22,948 fns, of which 6,535 are tests and 12 are `#[ignore]`d. Body extraction stops at the closing brace at the same indentation.
- Invariant tokens: every backticked snake_case or `::` token in every table row of `docs/04-invariants.md` (5,395 tokens; 3,842 with three or more underscores or a `::`). Each final segment was classified against the fn and test inventories: TEST 3,430, FN 332, NONE 80. Each NONE was resolved by hand with `git grep -w`.
- Ledger: `^#{1,6} D-[0-9]{4}` headings compared with every `\bD-[0-9]{4}\b` in tracked files. Conflict markers: `git grep -E '<<<<<<<|>>>>>>>'` and `^=======$`.
- 06-limits: every backticked path and every `fn`/`a::b` token was checked against the tracked tree and the fn inventory.
- One targeted run after BUILD_DONE: `cargo test -p store --test catalog -- a_store_root_that_cannot_be_searched_is_refused a_directory_the_walk_cannot_list_is_counted_not_dropped` (output below). I added no probe files. `git status --porcelain` shows only other workers' `zz_audit_*` files.

## Notes on part (2), tests that assert nothing
The scan found 42 test bodies with no inline `assert*`, `panic!`, `expect`, `unwrap` or `?`. I read every one. They fall into three groups:
- They delegate to an asserting helper, and I checked each helper: `where_permission_binds` (store, pull, api, telemetry; asserts the child ran exactly one passing test), `race_the_root`, `a_tier_resolves_to_its_published_list`, `kernel_heads_by_kind`, `contract_is_refused_by`, `under` (columns_tests.rs:28), `check_io_boundaries`, `check` (session_known_readiness.rs:177), `identical` (bootstrap_family_pass_tests.rs:70) and `each_renders` (write.rs:1137).
- They are `#[should_panic(expected = …)]`: limits_doc_drift.rs:181 and shared_core_doc.rs:446.
- They are the two compile-time-only tests in testgaps-10.

Three tests assert only `is_ok()`: core isin.rs:191, symbol.rs:176 and pull tests/tls.rs:53. In each, acceptance *is* the property, so they are not weak.
