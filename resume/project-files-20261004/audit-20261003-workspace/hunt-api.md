# hunt-api — server-side bug hunt in crates/api at 1087e54

**Verdict.** The HTTP admission layer holds up. It is loopback-only, checks `Host`/`Origin`/`Sec-Fetch-Site` on every write, refuses forwarded headers, refuses repeated query keys, and sends no CORS header. I found no path by which another browser tab can CSRF a pull, sweep, recovery or autopilot change. The recovery journal is careful: CRC, fixed stride, nothing published before `sync_all`, and an inode check. A torn tail is refused, not repaired, and that is deliberate. The prior probeapi rows 1, 2, 3, 4 and 7 are fixed. Row 5 is fixed for queries only.

The real defects are about what happens when work stops part-way, and about long-lived state:

- **(1)** `POST /pull/spot` and `/pull/fno` run the whole vendor pull inside the request. A client disconnect drops that future, which I proved with a probe on the crate's own `serve`. The pull's audit-journal record is then never written, and the telemetry run-id claim and the autopilot "now fetching" status are never cleared.
- **(2)** On Ctrl-C the process cannot exit while a sweep is running. The tokio runtime drop waits for the `spawn_blocking` sweep with no limit (proved).
- **(3)** A cross-site page can rotate the server's whole retained log away. 100,000 `no-cors`-style GETs evicted a sentinel event in 29 s (proved).
- **(4)** Recovery checks every stored attempt against the *current* build's F&O table before it filters by scope. One retired symbol in the shared ledger therefore blocks every recovery plan.
- **(5)** Repeated keys in a POST body are still read first-match-wins.

The Governor::reserve hang is fixed: the named test passes in 1.30 s.

Probes: `crates/api/tests/zz_audit_hunt-api_1.rs` and `_2.rs` were run, their output is quoted below, and both files were deleted. `git status --porcelain | grep hunt-api` → nothing (rc=1).

## Checked and holding (no finding)

- **CSRF / DNS rebinding** (`server.rs:16412-16700`): every non-GET/HEAD needs `Host` ∈ {`localhost`, bound IP} with the bound port, an exact `http://` `Origin` match, and `Sec-Fetch-Site` absent or `same-origin`. `Forwarded`/`X-Forwarded-*` are refused, and repeated headers are refused. Admission wraps the audit journal (`admitted`, 15872-15900). There is no `Access-Control-Allow-*` anywhere in api (grep: 0). Bind address: `loopback_serve_addr` refuses non-loopback (line 186).
- **Recovery journal** (`recovery_journal.rs`): `open_at` takes an exclusive flock, replays, rejects a length change, then `sync_all`s the file and its directory. Append checks the inode and length, writes, syncs, and only then publishes. Any I/O uncertainty poisons the handle. A torn tail refuses the open and is never truncated, by design (module doc; same policy as `pull.journal`, 06-limits §97 / J-04). Replay is idempotent: keyed latest-wins, and the same key with a different body is refused.
- **Recovery control lock order**: `run` is taken before `recovery_active` in `claim`/`pull_run_stop` → `stop`. No inverse order was found.
- **Credential law §8** (`credential_law.rs`): one re-read per rejection, compared by fingerprint. Same value → halt; transport vs. configuration classed; known-dead value refused before send; value never logged.
- **Governor::reserve hang**: `cargo test -p api --lib rolling_requests_spend_one_shared_permit_per_network_attempt` → `test server::fno_boundary_tests::rolling_requests_spend_one_shared_permit_per_network_attempt ... ok … finished in 1.30s`. `rate.rs:940-962` now returns `None` instead of `u64::MAX` on overflow, and `http.rs:686-692` refuses it.
- **Concurrent launches**: `/pull/run` claims `site.run` under one lock take (`server.rs:10882-10896`). Sweeps admit under the process-wide `ADMISSION` mutex plus the store execution lease (`sweeprun.rs:1663-1700`). Masters refresh is serialised by `REFRESH` (`mastersrun.rs:40`). The autopilot stands off a hand press via `site.run` and the per-feed seats (`autopilot.rs:3153-3173`).
- **/logs rendering**: every field, message and target goes through `render::escape` (`logs.rs:841-887`). There is no stored XSS from a logged attacker path.
