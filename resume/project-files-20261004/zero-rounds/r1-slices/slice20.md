# slice20 — 1 finding

## F1 [medium] An interrupted VIX companion publication wedges that single-stop catalog for good: `publish` treats "directory exists" as "already published"
- where: crates/cli/src/index_stop_vix.rs:386-397 (existence short-circuit), :406-408 (prepare/finish), caller crates/cli/src/index_stop.rs:415 (`publish_vix` inside the catalog commit)
- what: `index_stop_vix::publish` checks `symlink_metadata(root/index-stop-vix-reference-v1/<lookup>)`. If the directory exists at all, it returns `Reader::open(...)?` and never reaches `persistence::prepare_in_namespace`. But `prepare_in_namespace` (boolean_candidate_persistence.rs:87-130) creates that directory **first**, then `owner.lock`, then `body.bin`. Only `pending.finish` writes `complete.bin`. So any stop inside that window leaves a directory with no receipt. The causes include a process kill or OOM, a server stop, ENOSPC while writing `body.bin`, a failed `verify_body`, or a refused `catalog.with_current` lease after `prepare`. After that, every later `publish` for the same `(catalog, pin)` takes the `Ok(_)` arm. `Reader::open` then refuses ("saved VIX reference companion unavailable or invalid"), and the code never retries.
  - The persistence layer is designed to resume: `write_or_equal` accepts an identical `body.bin`, and `finish` can then add the receipt.
  - Every other publisher in this flow calls `prepare_in_namespace` directly and so does resume: the candidate catalog (index_stop.rs:399-403), `source_context::publish_body` (index_stop_source_context.rs:318-322) and `bind_catalog` (:391-395).
  - VIX is the only one that refuses.
  - The catalog identity is deterministic, so a rerun of the same single-stop batch recomputes the same `(identity, pin)`. It reaches index_stop.rs:415, which fails every time. The whole catalog goes to `refuse(catalog, ...)` (:438-447). That rung's batch can never complete, and the search cannot advance past it.
  - Nothing in the workspace cleans up this namespace: `grep index-stop-vix-reference-v1` finds only the constant and the namespace allow-list.
- evidence (trace):
  1. The first run reaches `publish` → NotFound → `catalog.with_current(|| { capture; encode; prepare_in_namespace(...)  /* creates dir + body.bin */ ; verify_body; finish })`. The process dies (or `verify_body`/the lease refuses) before `finish`, so `complete.bin` is absent.
  2. The rerun reaches index_stop.rs:415 → `publish` → `symlink_metadata(&directory)` is `Ok` → `Reader::open` → `Observation::open` needs `complete.bin`. The suite's own `index_stop_vix_missing_torn_or_corrupt_companion_never_backfills_on_read` (index_stop_vix_tests.rs:389-397) asserts that `open` errs with `complete.bin` removed. So `publish` returns Err, with no write and no retry.
  3. index_stop.rs:438-447 marks the catalog Refused. Step 2 repeats on every later launch.
  - No test exercises `publish` against a receipt-less directory. The only tests of the missing-receipt case go through `open`.
- fix: in `publish`, use the existence short-circuit only when `complete.bin` is present. Otherwise fall through to `capture` → `encode` → `prepare_in_namespace` (which accepts an identical `body.bin` through `write_or_equal`) → `verify_body` → `finish`. An identical recapture finishes the receipt. A differing body still refuses through `write_or_equal`'s "different or incomplete bytes" error. Minimal form: replace the `Ok(_)` arm condition with `Ok(_) if directory.join("complete.bin").exists()`. Add a test that deletes `complete.bin` after a publish, calls `publish` again, and expects the same `Reader` back.
