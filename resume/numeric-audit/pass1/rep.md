# SLICE=rep — global_replay.rs, global_replay_v2.rs, execution_v3.rs, execution_v4.rs (commit 331b05c)

## Verdict
No new medium- or high-severity finding. One info item about a bounded per-minute cost that the module docs understate. There is no PnL aggregation, no float arithmetic and no look-ahead path in these four files. Context: V1 and V2 are unreachable from any entry point (known, gaps-1). Execution V3 is `#[expect(dead_code)]`. Execution V3 and V4 are persistence and authentication ledgers with no price arithmetic.

No probe was built. The one item is INFERRED from source. Every "clean" claim below was checked by reading the code, not by measurement.

## Findings

### rep-1 (info): per-minute decision-to-stream mapping is O(offered^2), and the module docs state O(200 heads)
- global_replay.rs:750-768 (`find_offered_stream`), called once per decision from `record_decision` (:517-524). The same shape is in global_replay_v2.rs:3480-3498, called from :3378.
```rust
for index in offered.iter().copied() {
    ...
    if constituent_of(stream)? == constituent {
```
- Why: each of up to `offered` (at most 200) decisions in a minute re-scans the whole offered list and rebuilds a `Constituent` for every entry, which includes `instrument_of`, a `u16::try_from` and a struct compare. That is up to 200 x 200 = 40,000 constituent builds per emitted minute. The module docs (global_replay.rs:19-21, global_replay_v2.rs:30-32) only state "examines at most 200 stream heads per emitted minute". The cost is a bounded constant of the same class as the known `portfolio::canonical_order` (hunt-runner.md, at most 200^2). It is not unbounded and it does not violate §3.4, which names no replay primitive. An O(1) alternative exists: the scheduler could return the offered slot index, or the code could keep a map from constituent to offered slot per minute.
- Repro (INFERRED): 200 streams whose candidates all have the same `entry_micros` give 200 decisions in one minute and 40,000 `constituent_of` calls.

## Checked and clean
- **Event ordering / look-ahead in the merge:** `next_entry_micros` takes the minimum head. Only candidates whose `entry_micros` equals that minute are offered, and the scheduler sees no later minute. `GlobalSinglePositionV1::schedule_minute` refuses `entry_micros <= previous` (runner/portfolio.rs:425-435), so a repeated or backward minute is a loud refusal, not a silent reorder. The runner's replay also requires each stream's candidates to be strictly increasing in entry bar and stamp (grid.rs:3326-3330). Reopen (`replay_decision_block`, :2300-2364) groups decisions by contiguous `entry_micros` and runs a fresh scheduler, so a non-contiguous duplicate minute is also refused.
- **Occupancy across instruments, families, rungs and directions:** there is one global scheduler for all 200 streams. Occupancy is inclusive (`entry <= through` is blocked). A trade's `exit_micros` must equal the decision's `occupied_through_micros` (:2420-2421), so an admitted priceable trade cannot occupy less time than it was priced over. Constituent keys cannot alias: `strategy_digest` hashes family, rung, mask, direction and exit (population_admission_writer.rs:509-553), and `find_offered_stream` / `duplicate_ordering_key` refuse aliases.
- **Signal / entry causality fields:** decision validation needs `signal_micros < entry_micros <= occupied_through_micros` (global_replay.rs:1293-1297; V2 :883-884, :1490-1491). The IS/OOS split is enforced by the runner: `first_test_stamp <= training_last_ts_micros` is refused (exit_grid_policy.rs:2812-2823), and `validate_column_sources` checks the signal sources against `first_oos`.
- **VIX stamping (V1):** the stamp is the trade's own exact entry and exit minute, never a later or nearest one. `VixReferenceMonth::stamp` refuses a slot whose stored timestamp differs and returns typed `Absent` for a hole. The stored stamp must have `ts == entry_micros/exit_micros` (`validate_vix_stamp`, :1620-1643). Off-grid and unloaded months refuse. A feed mismatch refuses (:1688-1692). One note, not a defect: the entry stamp carries the full entry-minute candle, including that minute's H/L/C, which a fill at the open could not know. VIX is reference-only. It enters only `publication_id`, never selection, PnL, scheduling or `replay_id` (module doc :13-15; test `vix_changes_publication_but_not_selection_pnl_or_replay_identity`). So this is not a decision leak.
- **Fill prices:** none are computed here. `TradeRow` comes verbatim from runner `ReplayPriceV1` and is stored as i64 paisa, with no cast, rounding or float. Pricing-refused paths (BlockOnly/CrossingRefused) carry no money row by design. They are counted (`admitted_pricing_refused`, `pricing_refused_candidates`) and those counts are hashed into `replay_id` (:2061-2088). They are not hidden.
- **PnL aggregation / overflow:** no module sums best/worst PnL. Every counter (decisions, trades, ambiguous/gap totals, candidate totals, cursors, block ranges) uses `checked_add` / `checked_sub` / `checked_mul` with a named refusal. Quality ceilings (`absorb_quality`) are checked, and exceeding one refuses the whole replay.
- **Execution V3/V4 numeric:** the percentile strict-increase check uses `u64::from(u32) * u64::from(u32)`, which cannot overflow. `denominator == 0` and `numerator > denominator` are refused before the comparison (v3 :660, v4 :691). `PARAMETER_COUNT_PER_BLOCK as u64` and `READ_CHUNK_BYTES as u64` are widening casts. `axis as usize - 1` applies to validated enum discriminants 1..=3. The forced exit is a constant 15:10 bound in identity, with no time arithmetic. Training first and last stamps are checked `first <= last`.
- **Float use:** none in any of the four files outside tests.
- **Per-event lookups:** VIX month lookup is a `HashMap` keyed by `YearMonth`, then one fixed slot (O(1)). Execution-capability lookups are indexed. Known O(F) authenticated-lookup costs (F-D3D96B, 06-limits) are unchanged and not re-reported.
