# Fixed-training later qualification

This successor joins the complete original Boolean catalog to genuinely later
OHLCV, keeps every original exit coordinate, and records a full research-policy
comparison. Computation completion and an admitted research candidate are
different results. Neither is a live-trading or profitability assurance.

The new command is:

```text
cli boolean-qualified-campaign-stored VENDOR SYMBOLS FROM_Y FROM_M TO_Y TO_M CATALOG_FILE HORIZON MAX_POINTS OUTPUT_ROOT LATER_FROM_Y LATER_FROM_M LATER_TO_Y LATER_TO_M
```

Use the existing runtime policy and strict resource configuration. Dates,
symbols, program catalog, horizon and capture bounds remain explicit inputs;
there is no strategy depth parameter. The command preflights all eight existing
intraday timeframes and all requested families before allocating any later
qualification work. Existing grammar batches remain a separate research surface.
A finite qualification does not cover every other catalog or grammar batch.

The institutional comparison uses the existing common policy. Its execution,
profitability and Wilson observations describe the later frozen-coordinate
sample. PBO remains explicitly the original training-search diagnostic. The
later decided-window count, profitable-window count and aggregate pessimistic
return fill their own fields. Every failed, unavailable or refused field remains
present. No threshold is relaxed to force a passing candidate.

The zero-conservative numerical wrapper is a separately versioned implementation
choice. It retains full family order and identity, including zero candidates.
For positive observed thresholds, placing zero in a bootstrap maximum does not
change whether that maximum exceeds the threshold. Nonpositive observed
statistics are conservatively assigned probability one. A nonzero constant
series remains unsupported. This inherits the shared bootstrap assumptions;
it is not a finite-sample, distribution-free statistical guarantee.

Exact finite allocation applies to the predeclared candidate-specific test.
It does not permit selecting the smallest probability among methods, seeds,
catalogs or repeated studies. White and SPA remain additional conjunctive checks.
If the draw count cannot resolve the allocated threshold, the result says so;
draws are not silently increased after seeing outcomes.

The stored format uses a fixed 1,024-byte header, a versioned plan section,
128-byte family links, and fixed 1,024-byte candidate records. Each candidate
also reserves the complete 320-byte fold header and 64 bytes per declared fold;
an absent proof occupies canonical zero padding with an explicit absence tag.
The new namespace is `boolean-qualification-v1`. The scope journal is
`boolean-qualified-campaign-v1`; its eight slots never shrink to completed or
profitable subsets. Lifecycle operation15 is `boolean-qualification`.

The command prints `/backtest?boolean_qualified_campaign=<campaign-ID>` for the
automatic eight-timeframe progress table. It authenticates the bounded journal
history and labels whether each slot is waiting, running, refused or saved.
Each saved slot links to its exact qualification and completion pin. The overview
does not claim to authenticate child bodies; opening the corresponding detail
performs that separate bounded check and shows every policy result and reason.

History restore, source verification, statistical resampling, complete output
and the full search grow with the admitted input. Bounds make work and failures
explicit; they do not make those whole operations O(1). The MacBook's 14 CPU
cores and 48 GiB memory are capacity, not a measured speed guarantee. The
disconnected external drive contributes no available storage.

Verification must cite the actual tested source snapshot and measured outcomes.
Unit fixtures are generated test inputs and are never market-performance proof.
The previous campaign's successful checks do not automatically cover this new
successor. Full touched-crate line/branch coverage and mutation closure remain
separate repository completion gates.

The first retained-real check used April–May 2025 for training and June 2025
for later observation. It saved seven timeframe qualifications and explicitly
refused 60-minute observation: each instrument had only 147 committed, accepted
60-minute bars, fewer than the 200-fold trend warm-up requires. The active and
refused journal states both passed the actual dashboard handler and frontend
validators. This refused campaign is retained; it is not an eight-timeframe
success. A subsequent verification interval is declared as June–August solely
to provide enough coarse-timeframe history, with all policy thresholds unchanged.

The same check found that valid saved qualifications exceeded the dashboard's
64 MiB default ancestry allowance. The seven verified histories required
96,451,154–134,333,042 admitted serialized bytes. Runtime observation admission
must cover the complete saved ancestry; it is not a process-memory or latency
guarantee. A small default refusing larger evidence is visible incomplete
accessibility, not evidence corruption or proof that the result never existed.

`BRUTEX_BOOLEAN_OBSERVATION_BYTES` configures the server's complete Boolean
evidence allowance. An absent value keeps the 64 MiB default; malformed values
refuse. The command prints its corresponding bounded observation allowance and
the exact output root. Requests cannot raise the bound, and reducing it forces
cached evidence to be reauthenticated. Responses retain exact limits and reasons.
