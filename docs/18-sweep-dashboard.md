The HTTP contract is bounded and preserves exact identities:

| Route | Source and response | Refusal and resource boundary |
|---|---|---|
| /sweep-evidence.json?identity={64 lowercase hex}&kind=depth&page=0&limit=256 | Version 1 envelope, exact identity, latest attempt metadata, saved depth rows. All u64 counters and signed microsecond timestamps are decimal strings. | Maximum query 512 bytes, page 256 rows, selected kind 4,096 rows, each file 64 MiB, JSON 8 MiB. Empty, unknown or repeated query fields are rejected. |
| /sweep-evidence.json?identity={identity}&kind=ranked&page=0&limit=256 | Separate retained signal rows: six exact mask words, observations, support, wins/losses/refusals, and original IEEE statistic bits as decimal strings. | These are explicitly signal statistics, not priced trade rows. A ranked result above the selected-kind row cap refuses instead of exposing a prefix. |
| /sweep-evidence.json?...&page=1&attempt={page-zero token} | Every later page must name the page-zero attempt. Metadata is read before and after the bounded page. | A changed attempt or cardinality refuses. A missing old attempt cannot silently become a newer attempt's page. |
| /frontier.json | Cached validated parent indexes are refreshed first; one owned receipt is then reconciled with a freshly refreshed child handle. | A failed refresh is surfaced on that request and the handle is discarded. A later request may open a repaired generation; a successful reopen cannot hide the original refusal. |
| /trades.json | The same parent-before-child snapshot order, exact chosen-policy receipt and bounded row reconciliation. | No orphan child rows, invented policy or silent incomplete page is accepted. Existing 256-row pages and 4,096-row result cap remain. |
| /live.json | Decoded rows are reused for unchanged file generations. The directory is still measured on every refresh. | At most 4,096 directory entries, 128 named live runs and 256 rows per live run. A malformed named file, changed read or excess bound refuses the census; it does not become an empty successful census. |
| /engine/top.json | The terminal's canonical renderer consumes a cached best-record selection and parent-first verified frontier. Ties still choose the later record; halted rows remain excluded. | Query and files are bounded; blocking work is offloaded. Cold indexing reads history; warm selection refresh folds newly appended ledger records. Pair selection uses an ordered map and is not advertised as a universal O(1) lookup. |
| /backtest/run.json | An active browser slot is served directly. Otherwise the latest external command marker is selected from at most 256 lifecycle events on the bounded blocking worker door, using the CLI's canonical sweep-command classifier. | Inspection commands and per-attempt events cannot substitute for sweep-command completion. An observed active CLI wins over a finished browser slot even if it started earlier. Unreadable, malformed, clipped, truncated or scan-capped evidence is unknown. |
| /candidate-trades.json | Exact identity/attempt/model/catalog, selected tier and candidate rank/side; fixed trade and manifest readers authenticate the saved expression or AND mask. | At most 256 rows/page and 64 MiB per admitted file; continuations require the original catalog digest. Missing evidence is explicit. |
| /expression-search.json | Saved snapshot counters and learned checkpoint continuations, full expression text and exact child attempt/trade links. | At most 256 links/page, default eight; a shared 64 MiB verification budget is charged before child work. Expired or spliced continuations refuse. |

The shared blocking door admits at most **four queued or running reads** across these sweep detail/live/status/report surfaces. Evidence, frontier, trades, live and top overloads return an explicit refusal instead of enqueueing unbounded work. Status reports unavailable observation as unknown. This is bounded admission, not a latency guarantee: filesystem stalls, cold indexes, newly appended records, requested rows, directory entries, rendering and browser comparison all have real costs. Persistent history consumes growing storage; a cache or page cap does not make an exhaustive sweep or all retained history O(1) in time and space.

The frontend follows every frontier page before publishing ranking rows (frontier-pages.js, both backtest consumers). Saved depth evidence has a separate loader (sweep-evidence.js) which pins the attempt, checks exact counts and cursors, verifies ordered depths, preserves u64::MAX, and rejects mixed or malformed pages. Loading/unreadable evidence says **Not established**; only an explicit missing record says **Not recorded**. A recorded start with no terminal marker does not establish that a process is alive.
